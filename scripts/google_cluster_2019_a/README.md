# Google ClusterData 2019 — Cluster A preprocessing pipeline

Данный скрипт предназначен для выгрузки, фильтрации и подготовки подвыборки Google ClusterData 2019 Cluster A.

## Источник данных

Используется публичный датасет Google ClusterData 2019:

- Bucket: `gs://clusterdata_2019_a/`
- Основные таблицы:
  - `instance_usage-*.json.gz` — временные ряды фактического потребления ресурсов виртуальными машинами;
  - `instance_events-*.json.gz` — события жизненного цикла инстансов и информация о запрошенных ресурсах.

## Логика обработки

Пайплайн выполняет следующие шаги:

1. Получает список всех shard-файлов для `instance_usage` и `instance_events`.
2. Последовательно скачивает shard-файлы на локальный диск.
3. Обрабатывает данные потоково, чтобы не хранить полный датасет в оперативной памяти.
4. Формирует идентификатор виртуальной машины на основе `collection_id` и `instance_index`.
5. Применяет детерминированное hash-сэмплирование: `hash(vm_id) % 16 == 0`.
6. Сохраняет обработанные части в формате Parquet.
7. После обработки удаляет сырые shard-файлы.
8. После завершения объединяет usage- и events-данные.
9. Формирует итоговый датасет для EDA, feature engineering и моделирования.

## Выходные файлы

После успешного запуска в папке `out/` формируются:

- `usage_parts/` — обработанные части таблицы потребления ресурсов;
- `events_parts/` — обработанные части таблицы событий;
- `sampled_vm_ids.txt` — список отобранных виртуальных машин;
- `progress.txt` — журнал обработанных shard-файлов;
- `google_a_usage_sample.parquet` — объединенная usage-таблица;
- `google_a_events_requested.parquet` — таблица событий и запрошенных ресурсов;
- `google_a_final_joined.parquet` — итоговый датасет после объединения.

## Основные поля итогового датасета

Итоговая таблица содержит:

- идентификатор виртуальной машины;
- идентификатор коллекции;
- индекс инстанса;
- начало и конец временного интервала;
- временную отметку в минутах;
- среднее потребление CPU;
- максимальное потребление CPU;
- максимальное потребление памяти;
- запрошенный CPU;
- запрошенную RAM;
- относительные показатели потребления ресурсов к запрошенному объему.

## Установка зависимостей

Перед запуском необходимо установить Python-библиотеки:

```bash
pip install pandas pyarrow duckdb
Также требуется установленный Google Cloud SDK с доступной командой `gsutil`.

Проверка доступа к данным:

```bash
gsutil ls "gs://clusterdata_2019_a/instance_usage-*.json.gz" | head
```

Если команда возвращает список файлов вида:

```text
gs://clusterdata_2019_a/instance_usage-000000000000.json.gz
gs://clusterdata_2019_a/instance_usage-000000000001.json.gz
gs://clusterdata_2019_a/instance_usage-000000000002.json.gz
```

значит доступ к публичному bucket настроен корректно.

## Запуск

Из корня репозитория:

```bash
python3 scripts/google_cluster_2019_a/build_google_a_sample.py
```

Если запуск выполняется на Windows, команда может выглядеть так:

```powershell
python scripts\google_cluster_2019_a\build_google_a_sample.py
```

## Особенности

Скрипт рассчитан на длительную обработку большого датасета. Для надежности предусмотрены:

- последовательная обработка shard-файлов;
- сохранение промежуточных результатов;
- пропуск уже обработанных частей при повторном запуске;
- удаление сырых файлов после обработки;
- обработка некорректных JSON-строк без остановки всего процесса.

Это позволяет продолжать обработку после сбоя, отключения ноутбука или потери соединения.
